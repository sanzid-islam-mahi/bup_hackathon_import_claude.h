01 · The Problem
SECTION 01

What we had to build

Given a 24-hour campus energy scenario plus 1-3 natural-language operator notes, return a schedule that obeys every directive and minimizes cost.

↪

Input

24 hourly entries (demand, solar, tariff), a battery spec, and 1-3 operator notes in English.

⚙

Process

Interpret notes into 1 of 6 structured directive types. Apply them. Solve an LP.

↩

Output

A 24-hour schedule (grid, solar, battery per hour) plus totals: cost, grid kWh, peak.

03 · LLM Interpretation
SECTION 03

Operator notes → structured directives

The challenge

Natural language hides structure. Hidden cases will paraphrase. "Drop solar to 20%" and "leave roughly one-fifth" are the same directive.

Our approach

  • Tight system prompt with 10+ window phrasings
  • Factor = fraction remaining (0.2 = 80% reduction)
  • Hours: start inclusive, end exclusive
  • 3-layer validation (shape, Pydantic, model match)
  • Safe-fail to no_op on any uncertainty
// In:  "Reduce solar to 20% from 1 PM to 3 PM"

// Out:
{
  "note_index": 0,
  "applies": true,
  "directive_type": "solar_reduction",
  "structured_adjustment": {
    "hours": [13, 14],
    "factor": 0.2
  },
  "explanation": "Solar drops 80%..."
}

05 · Optimizer
SECTION 05

Linear programming, globally optimal

Formulation

  • 120 variables per 24-hour horizon
  • 5 per hour: grid, solar, charge, discharge, battery SoC
  • Objective: minimize Σ grid × tariff
  • 49 equality constraints (balance + continuity + end-of-day)
  • Variable bounds encode every directive

Solver

HiGHS via scipy.optimize.linprog — globally optimal, runs in ~5-20ms.

# Maximize objective
min  Σ g[h] × tariff[h]

# Energy balance every hour
g[h] + s[h] + d[h] - c[h] = demand[h]

# Battery continuity
E[h] = E[h-1] + c[h] - d[h]

# End-of-day neutrality
E[23] = initial_energy

# Directive bounds (per hour)
0 ≤ g[h] ≤ max_grid_window[h]
0 ≤ s[h] ≤ effective_solar[h]
c[h] = 0  if h ∈ no_charge

06 · Optimizer
SECTION 06

What if the LP fails?

LP solvers can return infeasible on weird inputs. We have a deterministic fallback that honors the same hard caps.

Fallback heuristic

  1. Use available solar first, up to demand.
  2. Fill the rest with grid, capped at max_grid_kwh.
  3. If grid cap leaves a deficit, discharge battery to cover it.
  4. Never violate no_charge, no_discharge, or min_reserve.

Why this matters

The judge checks both directive application and energy balance. If a scenario is infeasible, we honor the hard caps and accept an imbalance — better than violating a spec'd constraint.

In practice, this code path almost never runs on real cases — but it's there for hidden edge cases.

07 · Reliability
SECTION 07

Eight layers of resilience

Any single failure — rate limit, model outage, bad LLM output, LP infeasibility — should not crash the service or lose points.

01

Rate limiter

Per-IP, opt-in via env. Returns 429.

02

Pydantic

Schema rejection → HTTP 400.

03

Multi-model chain

Rotates on 429 / transient errors.

04

Gemini failover

Different provider if all Groq fails.

05

Per-note fallback

One bad note → that note becomes no_op.

06

All-notes fallback

LLM down → all notes become no_op.

07

Optimizer fallback

LP infeasible → heuristic with caps.

08

Sanitized 500

Generic message, no internal leak.
